# Business requirements

## Purpose

Provide a reproducible analytics platform for synthetic healthcare claims that helps operations, finance, network, and payment-integrity teams identify trends and prioritize review. It does not support clinical decisions, reimbursement determinations, or findings of fraud.

## Stakeholders and decisions

| Audience | Decision | Required view |
|---|---|---|
| Claims operations lead | Where are denial and adjudication delays concentrated? | Claim type, denial reason, month, appeal status |
| Finance lead | How do billed, allowed, paid, and member-responsibility amounts trend? | Monthly and specialty comparisons |
| Network manager | Which providers differ materially from specialty peers? | Provider volume, paid amount, denial rate, turnaround |
| Payment-integrity analyst | Which transparent signals should enter a review queue? | Pattern, provider, claim detail, signal counts |
| Data engineering | Can results be regenerated and moved to an enterprise warehouse? | Automated validation, dimensional model, Snowflake SQL |

## Functional requirements

- Generate deterministic synthetic data at demo, medium, and large scale profiles.
- Validate keys, counts, adjudication chronology, and financial reconciliation.
- Support SQLite locally and a Snowflake star schema for enterprise use.
- Provide reusable SQL, data marts, dashboard previews, a Power BI semantic model, and a guarded AI interface.
- Expose metric definitions, query logic, and limitations so results are auditable.

## Nonfunctional requirements

- No secrets or real protected health information in source control.
- A clean demo build and automated tests must pass in CI.
- Queries generated by AI must be read-only, bounded, allowlisted, and visible.
- Power BI artifacts must be text-based, versionable, and statically validated.
- Deployment must be reproducible through local Python or Docker.

## Acceptance criteria

The project is release-ready when the pipeline completes, tests pass, Snowflake validation queries return no violations, Power BI Desktop refresh succeeds with configured credentials, UAT scenarios pass, and documentation matches the implemented state.
